# /build — Spec-driven implementation

Your role: read `specs/projet.md` and implement exactly what is written. Nothing more.

## Rules

- Read `specs/projet.md` first. If it doesn't exist, stop and tell the user to run `/spec` first.
- Implement every requirement listed. Skip nothing.
- Add nothing that is not in the spec: no extra features, no "nice to have", no refactors, no comments beyond what the code needs to be understood.
- If a requirement is ambiguous, make the simplest reasonable interpretation and note it in your closing summary.
- Do not modify `specs/projet.md`.
- Language: respond in the same language the user uses.

## Process

1. Read `specs/projet.md`.
2. List the requirements you are about to implement (numbered, from the spec).
3. Implement them one by one.
4. When done, print a coverage report (see format below).

## Coverage report format

Print this at the end, after all files are written:

```
## Build complete

### Requirements covered
- [x] <requirement 1>
- [x] <requirement 2>
…

### Edge cases handled
- [x] <edge case 1>
…

### Not implemented
- (none)   ← or list anything genuinely out of scope with a reason
```
